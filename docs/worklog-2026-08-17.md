# 작업 로그 — 2026-08-17 · AdSense 2차 반려 대응(콘텐츠 확충·공개 범위 정리)

이 세션에서 수행한 진단·수정·검증의 스냅샷. (이후 변경은 이 문서를 갱신하지 않는다 — 최신 상태는 코드·CHANGELOG 기준)
릴리스: **v0.12.0 / v0.12.1 / v0.12.2**

## 1. 배경

AdSense 1차 심사(2026-08-01)의 지적 2건 중 **"게시자 콘텐츠가 없는 화면에 광고"는 해소**됐으나,
**"가치가 별로 없는 콘텐츠"만 남아 재반려**. 1차 대응이 *크롤러가 읽는 HTML*만 고치고
*리뷰어가 보는 화면*과 *콘텐츠의 독립 가치*를 놓친 것이 원인.

### 홈 구조 개편

- 상단 사이트 헤더 `.site-top` 48px(이름·설명·안내 5링크) + 하단 안내 띠 `.scroll-cue` 48px, `#game`은 `calc(100dvh - 96px)`
- **레이아웃 버그 3건**:
  - 블록 사이 **공백 텍스트 노드가 27px 줄 박스**를 만들어 안내 띠가 첫 화면 밖으로 밀림(헤더 추가 전부터 존재) → `body`를 플렉스 컬럼으로
  - 헤더 링크 터치 타깃 17px → `nav`에 `align-self: stretch` → 47px
  - `height` + `border` 합산으로 96px 예산 초과 → `box-sizing: border-box`
  - 360px에서 "개인정보처리방침" 넘침 → 이 헤더에서만 "개인정보"

### 공개 범위 정리

- **`.nojekyll` 추가** — Jekyll의 `.md → .html` 변환 차단, 개발 문서 HTML 18페이지 소멸
- `robots.txt`에 `/docs/`·`CLAUDE.md`·`CHANGELOG.md`·`README.md` `Disallow`
- 소스 주석 정정 — 로더 배치 근거를 '심사용'이 아닌 **'게시자 콘텐츠가 있는 페이지에만'**(정책 요건)으로
- 저장소 공개 설명 갱신(`도리도리 잼잼 10종` → `도리 12종`), 홈페이지 URL 연결

## 4. 검증

- **레이아웃 실측(puppeteer, 360/375/390/1440폭)**: 헤더 48px·링크 타깃 47px·안내 띠 첫 화면 노출·가로 넘침 0.
  일반 폰(390·360)은 `Scale.FIT`이 폭 기준이라 **캔버스 크기 손실 없음**(줄어드는 것은 레터박스뿐), 375·데스크톱만 5–8% 축소
- **광고 로더 배치 검증(브라우저 요청 추적)**: 홈·`guide-lotto`는 미로드(요청 0), 나머지 안내·읽을거리·FAQ·방침은 로드 — **방침 문구와 일치**
- **인프라**: sitemap 24 URL 전부 200 / http→https·www→루트·github.io→새 도메인 3종 301 / 없는 주소 404 / JSON-LD(WebApplication·FAQPage·Article) 파싱 성공 / robots.txt가 Mediapartners-Google·AdsBot 차단하지 않음 확인
- **정적 검사**: 태그 균형(strong·p·div·ul·ol·li·em·table·tr·td·th·h2·h3), 상대 링크 무결성, 제목·설명 중복 0, 이모지 0, `[임시]` 마커 0, `node --check`
- **수치 재검산**: `1 − 20·19·18/20³ = 14.5%` / `10·H(10) = 29.29` / `5·76/6 = 63.33` — 본문 값과 일치
- **배포 후 라이브 확인**: 개발 문서 18페이지 404, 신규 7페이지 200, robots·sitemap·헤더·출처 블록·방침 문구 반영

### 검증 도구 메모

puppeteer-core는 자매 프로젝트에 있다 — **`.cjs` 파일에서 정방향 슬래시 절대경로로 require**한다
(`require('C:/Users/moon/Project/fries-get-cold/node_modules/puppeteer-core')`).
ESM `import`는 `NODE_PATH`가 먹지 않아 실패하고, heredoc으로 쓸 때 `\\`는 소실되므로 정방향 슬래시가 안전하다.
`waitUntil: 'networkidle2'`는 CDN 때문에 타임아웃 나므로 `domcontentloaded` + 고정 대기를 쓴다.
Edge의 `--screenshot`은 캔버스 스케일이 어긋나 보일 수 있으니 **레이아웃 판정은 puppeteer `setViewport` 기준**으로 한다.

## 6. 남은 항목 (미착수)

- **재검토 요청 전 Search Console 연결 → sitemap 제출 → 색인 확인.** 색인 0인 상태로 요청하면 이번 콘텐츠가 평가에 반영되지 않는다
- **첫 화면이 여전히 캔버스**라는 구조적 한계는 남아 있다. 다시 반려되면 다음 후보는
  홈을 콘텐츠 랜딩으로 바꾸고 도구를 별도 주소(`/play` 등)로 분리하는 안 — UX 손실이 커서 이번엔 택하지 않았다
- 사이트 나이(약 1개월)·유입 부족은 콘텐츠로 통제 불가. 시간이 필요한 변수
- sitemap의 `lastmod`가 24개 URL 전부 같은 날짜 — 사실이라 조정하지 않았다(날짜 조작 금지)
- 이전 로그의 미착수 항목은 그대로: `visualViewport` 기반 자판 대응, 캔버스 터치 타깃 88px 전역 확대,
  낮음 버그(리셋 직후 유령 팡파르 3씬·악어 함정 이빨 10px 어긋남·CDN SRI 부재 등),
  `responsive-design.md` §10 DPR 서술 교정

## 7. 이 세션에서 규칙으로 승격된 것

[workflow.md](./workflow.md) §4에 편입:

- 분량 측정은 `wc -m`(바이트 아님)
- 심사·SEO 대응은 **렌더링된 화면 기준**으로 판정 — 모바일 도달 가능 여부까지 실측
- 페이지를 세트로 만들 때 **골격을 서로 다르게**(동형 템플릿은 자동 생성 시그니처)
- **"저장소에 넣는다 = 웹에 공개한다"** — GitHub Pages는 저장소 전체를 서빙하고 Jekyll이 기본 활성
- 확률·공정성 주장은 **반례를 직접 계산해 검증**
- `100dvh`를 나눠 쓰는 레이아웃은 합이 맞는지 실측, 고정 높이엔 `box-sizing`, 세로 스택은 플렉스 컬럼
- 정적 페이지에서 이모지뿐 아니라 **발음부호 붙은 라틴 문자도 회피**
